---
name: commit
description: 把当前改动整理成一次符合仓库规范的提交
---

把工作区的改动整理成提交。提交范围（为空则提交本次任务的全部改动）：$ARGUMENTS

1. 用 `git status` 看全貌，`git diff`（必要时 `git diff --staged`）看具体改动，`git log --oneline -20` 看这个仓库的提交风格。
2. 判断该拆成几次提交。互不相关的改动分开提交；只提交与本次任务相关的文件，用 `git add <路径>` 精确添加，不用 `git add -A`。
3. 写提交信息：主题行照仓库既有格式（本仓库是 Conventional Commits，带包作用域，英文、祈使句、小写、不加句号）；正文按包分组说明改了什么、为什么，以及**没有**采用的方案与理由。
4. 提交后报告：提交哈希、主题行、涉及的文件。

不要做的事：不加 `--no-verify`；不 amend 已推送的提交；不 force push；改动看起来不像用户想提交的，先问。
